# Mobile View Migration - Working Notes

## Current Baseline

- Frontend is vanilla JavaScript with script-tag-loaded IIFE modules and `window.*` namespaces.
- `main.js` remains the primary orchestration layer and contains compatibility wrappers around extracted feature modules.
- Existing mobile behavior is based on hidden/shown panels, floating controls, and swipe gestures.
- The active loop runtime is the pad-based Web Audio implementation in `loop-player-pad.js` and `loop-player-pad-ui.js`.
- Recommendations are implemented in `main.js`; the existing scoring behavior must be reused.
- Personal transpose is persisted through user data and LocalStorage, including `transposeCache`.
- The service worker is minimal and install-oriented; existing LocalStorage and delta-sync behavior is the practical cache path today.

## Design Decisions

### D-001: Three primary destinations

Home, Songs, and More are the only persistent mobile bottom-navigation destinations. Song Preview is opened from Songs and is treated as the performance surface.

### D-002: Catalogue and active setlist stay separate

The active setlist is application state, not the Songs screen's filter. Songs must always represent the full catalogue.

### D-003: Drawers preserve underlying state

Home, Setlist, Recommendations, Transpose, and Rhythm / Loop panels must close without resetting the current song, active setlist, filters, search, transpose, or scroll state unless the existing behavior explicitly requires it.

### D-004: Business logic stays in existing owners

The redesign should add mobile orchestration and presentation. Existing song, setlist, recommendation, transpose, authentication, cache, and audio functions remain authoritative.

### D-005: Desktop is protected

Mobile changes must be scoped to the existing responsive boundary or a deliberately selected replacement boundary. Desktop panel layout and controls are not part of this redesign.

## Risk Register

| ID | Risk | Mitigation |
|---|---|---|
| R-001 | Desktop layout regression | Keep mobile shell and styles behind the mobile breakpoint; run desktop smoke checks after each major phase. |
| R-002 | Duplicate event listeners | Use one-time initialization markers and keep module compatibility wrappers stable. |
| R-003 | Lost underlying state | Treat drawers as overlays and snapshot/restore only UI presentation state when needed. |
| R-004 | Catalogue becomes setlist-only | Keep active setlist state separate from catalogue filters and render paths. |
| R-005 | Transpose semantics change | Reuse current user-data/cache flow; never write personal transpose to song records. |
| R-006 | Recommendation context changes | Pass the current song through the existing preview and recommendation functions. |
| R-007 | Touch reorder failure | Retain existing behavior and add explicit reorder controls if device testing shows a problem. |
| R-008 | Small-screen loop overflow | Test six-pad layout at 360px and 375px before changing control arrangement. |
| R-009 | Offline expectations exceed implementation | Document current cache limits; do not claim full service-worker offline support. |

## Validation Log

### Architecture review

- Completed read-only inspection of the repository structure and core documentation.

### Phase 0 baseline

- Existing mobile initialization is delegated to `window.MobileUI.initializeMobileUI()` from `main.js`.
- Existing mobile controls are generated by `createMobileNavButtons()` and supplemented by swipe navigation.
- Existing panel state is represented by `.hidden` classes on `.sidebar` and `.songs-section`; the preview remains the underlying view when both are hidden.
- Existing floating controls are `.mobile-nav-container` and `.panel-toggle.draggable`.
- The current desktop/mobile boundary is `768px`, with desktop-specific rules beginning at `769px`.
- Phase 1 adds `.mobile-modern-shell` with exactly Home, Songs, and More. It hides legacy floating mobile navigation only under `body.mobile-modern-mode` and `max-width: 768px`.
- Home and Songs bridge to existing sidebar/songs panel behavior. More is reserved for the later app-level menu and does not introduce placeholder functionality in Phase 1.

## Out of Scope for the Initial Migration

- Backend API redesign
- Database schema changes
- Recommendation algorithm changes
- New audio engine
- Full service-worker offline caching rewrite
- Redesign of standalone admin workspaces
- Removal of existing desktop functionality
- Replacing existing feature modules with a frontend framework
